# Repository polish checklist

Tick each item. An item that does not fit the project gets a one-line reason, not a silent skip.

## Community files

- [ ] `LICENSE` with the exact license text; the README License section names it.
- [ ] `CONTRIBUTING.md`: how to set up, test, and open a pull request.
- [ ] `CODE_OF_CONDUCT.md`.
- [ ] `SECURITY.md`: how to report a vulnerability in private.
- [ ] `SUPPORT.md`: where to ask a question.
- [ ] `CHANGELOG.md`, with a release that matches the Release badge.
- [ ] `FUNDING.yml` when the project takes sponsors (this makes the Sponsor button).

## Templates

- [ ] Issue forms for a bug and for a feature request, in `.github/ISSUE_TEMPLATE/`.
- [ ] `.github/PULL_REQUEST_TEMPLATE.md` with a summary, test evidence and a checklist.

## Topics and SEO

- [ ] Repository description: one line that holds the key search terms.
- [ ] 5 to 10 topics: the product type, the language, the main nouns.
- [ ] Homepage URL set to the hosted product or the docs.
- [ ] The README first paragraph names the same key terms.

## Social preview

- [ ] A 1280x640 PNG (under 1 MB) made from the hero and the screenshot.
- [ ] No subtitle text on the image: the title and the screenshot are enough.
- [ ] Uploaded in the repository settings (Social preview).

## Final check

- [ ] The README renders on GitHub in light and dark mode.
- [ ] Every link and every image resolves.
- [ ] The badges show real values (CI is green, a release exists).
